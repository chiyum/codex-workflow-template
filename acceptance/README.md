# Acceptance 制度

每個任務一份凍結清單，每條格式如下：

```markdown
### A1 行為名稱
- 驗證步驟：使用者可重現的操作或命令
- 預期結果：可觀察且可判定的結果
```

大型或自主工作再加入以下任務憲章，並與 acceptance 放在同一份凍結清單：

```markdown
## 任務憲章（凍結）
- 範圍: <這次要動的>
- 非目標: <明確不做的；相鄰但未確認的對外行為也列入>
- 細節決策:
  - 需求內必要細節: <已確認內容>
  - 必要安全或正確性條件: <原因、影響與已確認內容>
  - 使用者已同意的可選改善: <無／逐項列出>
- 預授權決策: <純內部且不改可見行為、範圍、驗收、風險或成本的選擇>
- 必問白名單: <不可逆、付費、資安、正式環境、需求矛盾，或必須改已凍結邊界>
- 提問政策: <新想到的可選改善只記錄，不實作、不列為 blocker>
```

所有 code 新任務都先由使用者確認凍結；`auto` 只從凍結後開始自主執行。可選改善未獲確認不得進 acceptance、code 或 blocker。QA／PM 每驗一條都把證據放在任務 evidence 目錄，檔名包含 `A1-` 等條目編號。architect 更新的規格只供參考，不可取代已凍結清單。
