# ADR 使用規則

當任務涉及框架／資料儲存選型、重大架構模式、難回滾決策或推翻既有決策時，在產品 repo 的 `docs/adr/` 新增 ADR，並更新索引。一般 bug 修復或照既有規格的小改不需要 ADR。

最小格式：背景、決策、三方案比較、後果、回滾方式、驗證。ADR 與程式碼、測試、規格放在同一 commit。


# 凍結後的自主決策與續作

適用於需求與凍結事項已獲使用者確認的開發；唯讀任務不因此取得修改權。

## 凍結核心與實作補全

凍結核心包含產品目標、範圍、驗收門檻、核准的架構／核心引擎／主要依賴、資料與租戶／權限邊界、隱私，以及明確承諾的介面、流程、吞吐、品質、成本與資源限制。未逐項寫明的內部拆分、錯誤處理、輸入驗證、局部相容防護與合理預設值，只要不衝突上述承諾、可回退且可驗證，就可以補全；有可見回應或調整預設值不自動等於改凍結核心，但也不得藉「小防護」偷加相鄰功能、一般資安稽核或未授權依賴。

實作補全記在既有詳細設計或 decision log，關聯原規格 ID／版本與需求，註明自主決定，不得填成使用者個別核准；凍結規格本體不因同步實作文件而改寫。規格不可讀或版本衝突時，不造空殼、不以聊天摘要頂替，只隔離依賴該規格的工作。

## 分流

| 分流 | 條件 | 行動 |
|---|---|---|
| D1 自主決策 | 在已授權目標與凍結核心內；局部、可回退、證據足夠，無未授權成本、權限或外部副作用 | PM 職責與適用技術角色檢查，主 Codex 收斂、記錄，由 architect 實作、驗證後繼續 |
| D2 非阻塞待決 | 資訊或必要角色判斷不足，但可證明隔離，且仍有其他已核准的獨立必做工作 | 記錄未知、選項、依賴、owner 與升級條件；暫停相依部分，實際轉做獨立工作 |
| D3 需人工決策 | 核心架構或凍結承諾要改、越過授權邊界，或待決已阻塞主要後續工作 | 揭露證據與具體方案並詢問，停止相依實作；可證明獨立的工作仍繼續，未回覆不算同意 |

已知核心變更即屬 D3，不得藏成 D2。資訊不足先做定點查證；命名、排版或沿用既有慣例且無實質取捨者，不另召集 agent。

## 角色協作不新增 gate

- Full 由既有 PM 提供產品觀點；Standard／Lite 由 verifier 承擔 PM 職責。諮詢不是新的 acceptance、review 或 QA gate，不改 ordered gates、profile 或最終獨立驗收責任。
- 技術觀點由 architect 或適用領域 agent 提供，只有主 Codex 派遣；寫入仍只由 architect。security-auditor 仍只依原本觸發條件啟動。
- 同等可行方案由主 Codex 依既有慣例、較小影響、回退與可驗證性取捨；PM 指出的凍結衝突、實質風險或證據缺口必須處理，不能多數決壓過。
- 保存真實 agent 名稱／ID 與輸出引用；必要角色不可用時標 `AGENT_UNAVAILABLE`，不得由主 Codex 自評代替獨立審查，只暫停需要該判斷的決策。

## Decision log 與續作

沿用 `state/<task>-questions.md`（或任務既有決策檔／ADR）記錄每筆有實質影響的 D1 及所有 D2／D3：

```text
DECISION ID／關聯規格 ID、版本、需求：
問題與影響／已知與未知／適用凍結承諾與查證來源：
分流 D1|D2|D3／是否阻塞主線：
參與者與輸出引用（不可用則 AGENT_UNAVAILABLE）：
選項、結論與未採理由：
狀態：已決待實作|已實作待驗證|已驗證|待資訊|待人工核准
相依項／可繼續需求及獨立性依據：
所需資訊或核准／owner／重新檢查與升級觸發：
修改位置／驗證與回退：
核准：D1 記任務授權；D3 記使用者明確核准引用，未核准不得填同意
```

獨立工作不得依賴未定介面、資料結構或核心選型，只能從原需求選，不能為保持忙碌加功能；fixture／mock 只用已核准契約。有獨立工作時 state 保持 `running`，`next_action` 指向該工作與 decision log；D2 變成主線前置、無法隔離或沒有其他獨立必做工作時升 D3。續作先讀原規格版本、decision log、state 與 handoff，核對當前程式與核准狀態，不重問已核准決策，也不把待決當通過。必做需求或必要 gate 未完成時只能回報部分完成，不得標 `done`。

## 決策請求與權限

D3 詢問包含：決策 ID、原核准、目前證據與限制、為何不能自主、方案建議與代價、已停止部分、可繼續項目與請核准的具體選擇。產品小決策權不等於工具、安全或發布權：付費、資料／憑證、主動掃描、正式環境與既有 review/test/evidence 規則照常，PM 不代替使用者核准；「自主完成」不額外授權 commit、push 或部署，當次明確禁止者優先。
